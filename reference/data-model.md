# Data model

## One record = one file
`records/issues/NNNN.md`, `records/commits/SEQ-hash.md` (and `records/z2/...` for the secondary corpus). A markdown file with a **JSON-valued frontmatter** (valid YAML), a `## Summary` and a `## Notes` section:

```
---
kind: "issue"                 issue | commit
repo: "z2"                    only in the secondary corpus
pr: false                     issue records: true for a pull request
id: 1836                      issue number, or commit sequence number (git log --reverse)
hash: "c66fda2"               commits only (short hash; the filename anchors on it)
title: "..."
url: "https://github.com/OWNER/REPO/issues/1836"
date: "2025-10-27"
state: "closed/completed"     issue: open | closed[/completed|/not_planned]; PR: pr-merged | pr-closed | pr-open
files/adds/dels: 12/340/20    commits: touched files, added and deleted lines
refs: [1836]                  commits: issue numbers found as #N in the subject
status: "analyzed"            stub | triaged | read | analyzed   (only moves up)
depth: "full"                 title | thread | full | source     (only moves up)
tagged_by: "manual"           none | heuristic | manual
classes: ["D3", "M1"]         problem class ids cited by hand (taxonomy/classes.json)
classes_inferred: ["O1"]      suggested by a model (a ~ prefix in a batch); never mixed with classes
tags: ["cause:byte-cutoff", "layer:probe", "conf:stated"]     facet:value, controlled
cited_in: ["analysis/10-measurement-validity.md"]              filled by backfill-docs
---

## Summary
One or two sentences, in your own words.

## Notes
Free text (rarely used).
```

## Ladders
- **status:** `stub` (bootstrap only) -> `triaged` (heuristic tags) -> `read` (someone read the source text) -> `analyzed` (manual tags plus summary). A batch line defaults to `analyzed`.
- **depth:** `title` -> `thread` (opening post plus the first maintainer replies) -> `full` (whole thread from the complete API list) -> `source` (also checked against code, docs or a newer version). For commits: `title` = subject and file list only; `source` = the diff was read.
- **tagged_by:** heuristics never count in statistics; only `manual` tags do.

## Refs (used in batches and `pz show`)
`i1836` issue/PR number · `c66fda2c` commit hash prefix · `z2i75`, `z2c1a2b3c` secondary corpus.

## Derived files (never edit by hand)
`STATE.json`, `indexes/*` are generated by `pz.py status --write` and `pz.py index` and can be deleted at any time.

## Other directories
`batches/` archived tagging passes · `taxonomy/facets.json` (controlled vocabulary: `{"facets": {name: {"multi": bool, "doc": str, "values": {value: meaning}}}}`) · `taxonomy/classes.json` (`{id: {"title", "doc"}}`) · `analysis/` narrative documents · `brainstorms/` session entries · `data/` API lists.

## Why files, not a database
Diffs are reviewable, history is git, records survive tool changes, any language can read them, and a replay from batches rebuilds everything.
